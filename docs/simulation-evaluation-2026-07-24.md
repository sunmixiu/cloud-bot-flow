# 机器人仿真实验室多 Agent 评估与优化报告

日期：2026-07-24

## 结论

前端、后端和机器人仿真工程三个方向独立评估后的共识是：原版本适合内部 UI
演示，但前端合成动画、固定 0 碰撞和公式化 CPU/内存不能作为算法正确性或发布
门禁。优化后的版本可用于“算法资产编排、契约预检和故障流程演练”，仍不能代替
Docker + ROS 2 + Gazebo/Isaac 的物理仿真。

## 三个方向的主要发现

### 前端

- 原进度每 420 ms 固定增加，成功状态和指标由浏览器生成。
- 进入仿真前已经调用部署接口，仿真和生产部署语义混淆。
- 运行中仍可修改机器人和算法链。
- 名称模糊匹配可能导入错误算法，移动端存在横向溢出。

### 后端

- 原通用 `PUT` 可覆盖运行状态、进度和指标，没有状态机。
- 预检只比较 Topic 名称，未知算法和未知场景可能通过。
- JSON 直接覆盖写入，缺少串行、原子替换和备份。
- 旧运行在服务重启后可能永久停留在 `running`。

### 机器人仿真工程

- MoveIt、Nav2、SLAM 和 RMF 缺少机器人/场景兼容约束。
- ROS 消息类型、机器人能力、场景能力和最小机器人数量没有校验。
- 合成模式没有故障注入、固定 seed 和不可变运行清单。
- 真实仿真还缺少 Simulator Adapter、ROS bridge、控制器、遥测和工件。

## 本轮已完成优化

1. 当前模式统一改为“浏览器编排演练”，完成结果永久 `publishable: false`。
2. 物理碰撞显示“未测量”，容器 CPU/内存显示“未连接”。
3. 前端轮询后端运行快照，不再提交成功状态或物理指标。
4. 运行记录只能通过暂停、恢复、取消控制端点迁移；旧 revision 返回 409，通用
   `PUT` 返回 405。
5. 预检只接受已注册算法 ID，可校验版本、机器人资产、机器人类型/能力、场景、
   Topic 生产者和 ROS 消息类型。
6. 增加仓储移动机器人、机械臂操作单元和 RMF 多机器人楼宇三个场景契约。
7. 增加固定 seed、故障模式、算法顺序/版本/commit 和 SHA-256 运行清单。
8. 增加传感器中断、算法超时两种合成安全故障演练。
9. JSON 写入改为串行临时文件、解析校验、备份和原子替换；旧版非终态运行会在
   启动时进入 `interrupted`。
10. 工作流拓扑增加环路阻断，保留算法顺序；进入仿真实验室前不再调用 `/deploy`。
11. 活动运行锁定算法、机器人、场景和故障模式；增加键盘可操作的“加入运行链”
    按钮。
12. 375 px 视口已消除页面横向溢出，并支持 `prefers-reduced-motion`。

## 投入使用边界

现在可以投入内部使用的范围：

- 算法资产登记和开源算法目录浏览；
- 工作流拓扑检查和算法顺序传递；
- 机器人/场景/ROS 接口契约预检；
- 暂停、恢复、取消和故障流程演练；
- 运行清单、事件和审计演示。

仍不能用于：

- 判断算法精度、稳定性或实时性能；
- 碰撞检测、轨迹误差和安全认证；
- 以仿真结果直接批准生产发布；
- 真实 Docker/ROS 2/Gazebo 执行。
